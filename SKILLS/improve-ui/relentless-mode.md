# Quality Loop

Continue until the requested UI outcome is evidenced. Not permission to widen scope, edit during a read-only audit, or treat taste as fact.

## Start

Profile: `micro`, `focused`, or `deep`. Requested bar and stop condition. Capture current state before a visual, interactive, responsive, or performance change. Visible symptom → user impact and source cause. User-facing path, constraints, proof target explicit.

## Iterate

1. Fix the highest-severity in-scope issue.
2. Smallest systemic repair when instances share a cause.
3. Preserve unrelated behavior and user changes.
4. Narrowest relevant source/test/runtime check.
5. Inspect the same state plus one relevant edge or recovery state.
6. Repeat while evidence still shows an unresolved P0/P1 or repeated systemic P2 caused by the touched path.

Don't use repeated iteration to add unrelated redesign, dependencies, or product behavior.

## Reject False Completion

Do not stop on:

- advice-only output when the user authorized implementation and the source is editable
- detector-only report presented as visual judgment
- compilation or typecheck presented as UI proof
- screenshot from a different route, viewport, state, theme, or content
- state names listed without setup, action, assertion, and successful run
- "looks better" without an artifact or clearly limited claim
- unresolved in-scope P0/P1 findings hidden by an aggregate score
- clean default state while the changed edge or recovery state still fails

## Challenge Precisely

Direct, evidence-backed:

- "The main blocker is … because …"
- "The interface prioritizes X, while the task requires Y."
- "This patch is local, but the repeated cause is …"
- "I am not calling this verified because …"

Avoid vague phrasing ("improve hierarchy," "reduce clutter," "make it modern") unless followed by exact removals, merges, promotions, and proof.

Rigorous toward the artifact, collaborative toward the user. Match requested tone. Don't manufacture hostility.

## Stop

Stop only when one is true:

- evidence meets the requested bar
- remaining issues are outside authorized scope and recorded as risk
- a specific blocker prevents implementation or proof
- the user explicitly requested a quick/read-only assessment

If evidence is incomplete: "implemented, not fully verified" or "reviewed, blocked by …". Never turn elapsed effort into a pass.
