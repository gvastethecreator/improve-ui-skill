# Final Checklist

Apply only items relevant to the chosen profile and claim. Mark `n/a`, `unknown`, `blocked`, or `verified`. Do not imply universal coverage.

## Scope And Authority

- [ ] Work-unit id, existing web UI target, user path, profile, primary archetype, bounded regions, user mode, primary artifact, pressure, input, spatial model, register named. Unrelated archetypes split.
- [ ] Diagnose/verify/audit/review did not edit source or persistent artifacts, or implementation/report authority is explicit.
- [ ] Temporary diagnostics stayed outside the project. Durable report output explicitly requested.
- [ ] Unrelated user changes and preserved contracts intact.
- [ ] Opened references were the minimum set that changed decisions.

## Diagnosis And Change

- [ ] Main task, visible symptom, user impact, source cause connected.
- [ ] Context delta: what this archetype requires, what evidence shows, why the mismatch harms its real user loop.
- [ ] P0/P1 handled before taste.
- [ ] For `focused`/`deep` work, improvement inventory exists. Every in-scope row closed or `blocked` with a reason.
- [ ] Repeated defects repaired systemically when safer than local patches.
- [ ] Main path plus one relevant edge or recovery path addressed for nontrivial work.
- [ ] Archetype-specific costly states run or marked `unknown`/`blocked`. Generic breakpoint proof did not replace them.
- [ ] No unrelated redesign, dependency, or behavior entered scope.

## Contracts

- [ ] Semantics, accessible names, keyboard, focus, and status behavior preserved or improved.
- [ ] Applicable forms, validation, pending, failure, recovery states work.
- [ ] Responsive layout survives relevant boundaries, zoom/reflow, and real content.
- [ ] Applicable loading, empty, error, permission, stale, long-content, locale, repeated-action states run or marked unknown/blocked.
- [ ] Changed UI copy preserves facts, product voice, stable terms, legal text, variables, translation tokens, visible and accessibility name alignment, and the user's action or consequence.
- [ ] Loading, empty, no-result, permission, error, success, recovery copy verified in each changed state and relevant viewport.
- [ ] Motion has purpose, interruption behavior, reduced-motion path, and appropriate input gating.
- [ ] Performance claims use measured evidence. Source-only cleanup labeled as risk reduction.

## Finish Craft

- [ ] H/V anchors, baselines, control/icon centering, repeated row/column alignment inspected in rendered evidence.
- [ ] Internal padding, sibling gaps, group gaps, section spacing distinguished and repeated intentionally.
- [ ] Every actual scroll region has correct ownership and a minimal theme-aware custom scrollbar. Affordance, forced colors, keyboard, wheel, touch, zoom remain usable.
- [ ] Gradients judged by role, stops, contrast, banding, clipping, fallback, themes, performance — not banned or approved by hue alone.
- [ ] Icons use a coherent source or family. Custom vectors passed real-size and enlarged-crop inspection for geometry and optical centering.
- [ ] Material report prose passed the copy/writing final read. Named patterns remain advisory unless project policy makes them a gate.
- [ ] Finish ledger contains no applicable `failed`. Each `blocked` limits the claim.

## Evidence

- [ ] Before/after visual proof uses the same route, state, viewport, content, theme.
- [ ] Structured proof artifacts exist. Hashes and metadata verify when strict proof is claimed.
- [ ] Named runtime states completed successfully and passed assertions.
- [ ] Objective detector findings and advisory heuristics remain separate.
- [ ] Assessment, evidence coverage, expectations, gates remain separate.
- [ ] Uninspected dimensions remain `unknown`. No total score hides them.
- [ ] Exact commands, exit status, artifacts, environment metadata recorded where relevant.
- [ ] Browser/runtime blockers and claim limits explicit.
- [ ] Small-detail claims use device scale factor `2` evidence or readable focused crops. Compressed or tiny captures are not finish proof.
- [ ] Every durable JSON record has a same-facts `.md` companion. Material reviews and proposals include synchronized `report.md`, `report.html`, and lossless local report assets.
- [ ] Every screenshot annotation names one literal subject, matches its numbered overlay and automatic zoom, and records the same normalized geometry in Markdown.

## Closeout

- [ ] Final answer leads with findings for review or result for implementation.
- [ ] Source findings cite file/line. Visual findings cite viewport/state/artifact.
- [ ] Standards, practices, heuristics, preferences labeled correctly.
- [ ] Files changed, proof, skipped checks, blockers, remaining risk named.
- [ ] "Verified," "production-ready," and conformance language do not exceed the evidence.
